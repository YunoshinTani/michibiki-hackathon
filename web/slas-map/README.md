# みちびき測位モニター

QZ1 GNSS シリアルモニターをもとに、受信機の位置と測位情報をブラウザーに表示するローカルサイトです。NMEA解析は同梱の `gnss_core.py` が行います。

## 起動方法

1. Python 3 をインストールします。
2. 初回だけ `setup.bat` を実行します。
3. `start.bat` を実行します。
4. ブラウザーで `http://127.0.0.1:8765` を開きます。
5. GNSS受信機をUSB接続し、ポート一覧から `COM番号` を選び、通信速度を設定して「接続」を押します。標準値は `115200` baud です。

サイトはこのPC内 (`127.0.0.1`) だけで待ち受けます。終了するときは `start.bat` の黒い画面で Ctrl+C を押してください。

## 地図とデータ

地図ライブラリとOpenStreetMapの地図タイルをインターネットから読み込みます。GNSS受信と数値表示はローカルで動作します。地図タイルの読み込みに失敗した場合も、緯度・経度などの値は表示されます。

Fixが取れている位置をマーカーと軌跡で表示します。ローカル表示では、接続中の軌跡をメモリー上に保持し、次回接続時に新しい軌跡へ切り替えます。ローカル表示中は位置や受信データをファイルや外部サービスへ送信しません。

バッテリー電圧は V 単位で表示します。

## Windows PC からyahikoサーバーへ送信

`send_gnss.py` はWindows PCのシリアルポート（既定: `COM16`、`115200` baud）からNMEAデータを読み、1秒ごとに最新状態をHTTPSで送ります。シリアル接続ごとに新しい記録を作り、Fix位置をサーバーへ追記します。起動例:

```bat
.venv\Scripts\python.exe send_gnss.py --url https://www2.st.nagaoka-ct.ac.jp/~ec36104x/michibiki/gnss_api.cgi?action=ingest
```

yahikoの公開サイトのBasic認証ユーザー名とパスワードは起動時に入力します。認証情報はファイルに保存しません。位置情報を保護するため、送信先はHTTPSに限定しています。

COM16は同時に1つのプログラムしか開けません。送信中はローカル画面でCOM16を接続しないでください。

### 比較用GPS受信機から直接送信する

1. QZ1 に加え、NMEA 0183 を出力する比較用受信機を Windows に接続します。GPS 単独との比較試験では、比較用受信機を GPS 単独に設定してください。送信プログラムは受信機の衛星設定を変更しません。
2. VS Code の「タスクの実行」で **みちびき測位モニター: COMポート一覧** を選び、比較用受信機のポートを確認します。分かりにくい場合は、接続前後の一覧を比べてください。
3. **みちびき測位モニター: QZ1とGPS受信機を送信** を選び、手順 2 の COM 番号と受信機の通信速度を入力します。QZ1 は `COM16`、`115200` baud で開きます。
4. Basic 認証の情報を入力し、端末に「比較用受信機: 測位を受信しました。」と表示されることを確認します。公開サイトの「測位比較」タブで、その回の記録を開きます。

PowerShell から実行する場合は、`web/slas-map` フォルダーで以下を実行します。`COM17` と `9600` は比較用受信機に合わせて変更してください。

```powershell
.venv\Scripts\python.exe send_gnss.py --list-ports
.venv\Scripts\python.exe send_gnss.py --url "https://www2.st.nagaoka-ct.ac.jp/~ec36104x/michibiki/gnss_api.cgi?action=ingest" --gps-port COM17 --gps-baud 9600
```

この方法では比較用の測位を COM ポートから取得するため、ブラウザーで位置情報を許可する手順は不要です。測位が取れていない場合や、最後の測位から10秒を超えた場合は、その回の比較位置を送信しません。

### PC の推定位置を比較する

```bat
.venv\Scripts\python.exe send_gnss.py --url "https://www2.st.nagaoka-ct.ac.jp/~ec36104x/michibiki/gnss_api.cgi?action=ingest" --pc-location
```

送信プログラムに表示された `http://127.0.0.1:...` の URL を送信元 PC で開き、「位置情報を許可して送信」を押します。位置情報が許可されていない場合は Windows とブラウザーの位置情報設定を確認してください。送信中はこのページを開いた状態にします。yahikoの公開サイトを開く端末の位置はこの比較に使いません。

PC の位置は Wi-Fi などからの推定値の場合があります。

### iPhone の測位を比較する

Windowsでは **みちびき測位モニター: QZ1とiPhoneを比較** タスクを実行します。iPhoneのOwnTracksには、そのタスクが表示する記録専用のURLを設定します。詳しくは [iPhoneの送信手順](server/README.md#iphoneの位置をowntracksから送信) を参照してください。

### 公開サイトで記録を確認する

青の実線は QZ1、橙の破線は比較側です。2点間の距離は同時刻に近い測位同士の差を表します。精度を評価するときは、既知の地点に両受信機を置き、「基準点からの距離」で各測位のずれを比較します。みちびきの補強効果を示すには、QZ1 の補強適用を別途確認して記録してください。

グラフを横にスライドすると中央のカーソルの時刻が変わり、地図がその時刻までの最後の測位点に移動します。「情報一覧」に切り替えると、同じ時刻の衛星数、高度、速度、進行方位、受信統計などを確認できます。情報一覧でも時刻を変更できます。保存データがない項目は未記録と表示します。グラフでは欠測区間の前後に記録がある場合、推定した変化を点線でつなぎます。「記録の最終値に戻る」で通常表示に戻ります。

「分析」は QZ1 の経路と速度・高度の履歴を集計します。「測位比較」を開くと比較側の経路も表示し、測位時刻が近い2点間のずれを集計します。速度・高度や時刻が保存されていない旧記録では、利用できる項目のみ表示します。

比較側の位置に推定精度が付いている場合は、その値を経路と一緒に保存し、過去の位置でも円の半径として表示します。既存の記録は、同じ測位時刻の推定精度が残っていれば表示できます。

測位点の間隔が10秒を超える区間は、地図では前後の測位点を細かい点線で結びます。再生中は記録された時刻に合わせてその線上を移動します。累積距離や分析の距離には、この区間を加算しません。

各時刻の測位情報は、更新版 CGI を配備し、最新版の送信プログラムで送信を始めると保存されます。過去の記録も、すでに保存された位置や時刻を引き続き閲覧できます。送信時刻ごとに、その回の受信で更新した測位項目と累積の受信統計を保存します。

過去の接続記録は閲覧サイトの「表示する記録」から選択できます。経路の点数上限はありません。既存の `latest.json` があれば、残っている経路を初回アクセス時に「既存記録」として移行します。yahikoサーバーへの配置手順は [`server/README.md`](server/README.md) を参照してください。Python 2.7.5対応の受信CGIを`server/gnss_api.cgi`に用意しています。yahikoサーバーなどlocalhost以外で開くと、シリアル操作を隠した遠隔閲覧画面に自動で切り替わります。`?view=remote`を付けても同じです。

画面の `standard.css` は、`V:\5_server\tani-server1-dev\web\common\public\standard.css` から取り込んだ共通デザインです。共通デザインを更新した場合は再コピーしてから公開してください。
